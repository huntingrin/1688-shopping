# 下单执行

默认只读。只有用户明确说出"下单""买""帮我买""拍下"这类授权时，才进入本流程；一句"帮我找"不算授权。

支付始终由用户本人完成。可以提交订单、可以进收银台，不可以代付、不可以代填支付密码、不可以代替扫码。

## 前置条件

| 条件 | 要求 | 缺了怎么办 |
|---|---|---|
| 登录态 | 1688 PC 下单必须登录 | 让用户扫码或账密登录，交接当前页面；不要导出 Cookie、不要换账号 |
| 商品 | 用户已确认的链接 | 先交付候选并等确认 |
| 规格 | 颜色 + 尺寸 + 数量三者齐全 | 回到详情页选，不要默认第一项 |
| 收货信息 | 姓名、手机、省市区、详细地址 | 向用户要，不要从历史订单推断，不要用他人地址 |
| 支付预期 | 用户知道会走到付款页 | 若无明确"到付款再找我"，提交前先说明 |

## 六步流程

1. **详情页选规格**：颜色用真实指针点击，尺寸行单独加数量。做法见 [页面操作配方](dom-recipes.md)。
2. **点「立即下单」**：进入 `order.1688.com` 确认订单页。此步只是结算，不产生扣款。
3. **核对商品行**：页面会写全 `颜色:xxx;尺寸:xxx`，逐字比对，尤其确认颜色没有被回退成默认值。
4. **处理地址**：选择已有地址或新建，然后**必须点「确定」**让地址挂到订单。顶部由「请添加地址」变成完整地址才算成功。
5. **核对合计**：商品小计 − 店铺优惠 + 运费 = 应付。截图或记录每一项。
6. **点「立即下单」→ 收银台 → 停**。不点「立即付款」。

## 提交前检查清单

- 颜色与实际想要的一致，不是页面默认的那一项
- 尺寸落在用户给的净开口范围内，不是"外框尺寸"
- 数量为 1 时确认没有被购物车里的旧件合并
- 收货人姓名、手机、区县逐字正确（自动识别常错，见 dom-recipes）
- 合计金额在用户预期内；超出就先问，不要"先下了再说"
- 订单页显示的预计送达日期已记录，用于后续交付

## 收银台：默认是「先采后付」

1688 收银台对已开通该服务的账号**默认选中「先采后付」**，页面显示：

```text
￥0.00
确认收货后付款 ¥66.00
请在4天X时X分 内完成支付
[先采后付] 确认收货后付款 · 收货后下月8号自动付   ← 默认勾选
[支付宝]   大额订单推荐使用网商卡支付
[立即付款]
```

含义：现在 0 元，确认收货后下个月 8 号自动扣款。这是信用支付，不是免费。

另一条路是切到「支付宝」当场付款。

**不要把进入收银台说成"已购买"或"已付款"。** 正确说法是"订单已提交、未付款、停在收银台"。

未支付订单保留约 **4 天 23 小时**，超时自动取消，不产生费用、不影响信用。

## 交付话术

按这五项报给用户，缺一不可：

1. 订单号
2. 商品：颜色 + 尺寸 + 数量
3. 金额构成：商品价 + 运费 − 优惠 = 合计
4. 收货信息是否已挂到订单
5. 剩余支付时间，以及默认支付方式是「先采后付」还是「支付宝」

同时说明：支付需要用户本人完成。可以把收银台页面留在浏览器里交接，也可以给订单号让用户在手机 App 里付。

## 失败与边界

- **静默失败**：地址未挂到订单时点「立即下单」，页面不跳转也不报错。不要反复点，回去检查地址。
- **限购或库存不足**：如实告知，不要拆单、换账号或换 SKU 凑单。
- **价格在提交页变了**：以确认订单页为准，变化超过用户预期就停下来问。
- **验证码/人脸/短信**：一律交给用户，不代过。
- **取消订单**：用户反悔时去「我的订单」取消，不要口头承诺"没付就没事"——先确认取消成功。
